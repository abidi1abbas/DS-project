# Roman Urdu Sentiment Analysis

Phase 1 of a data science/NLP project that prepares a Roman Urdu sentiment
dataset for later comparison of classical machine learning, deep learning, and
transformer models.

## Problem statement

Online text contains useful opinions, but manually reading thousands of messages
is slow and impractical. The final project will classify a Roman Urdu sentence as
positive, negative, or neutral. Roman Urdu is challenging because spelling is not
standardized, messages are informal, and the same idea can be written in many ways.

Phase 1 covers only data loading, cleaning, exploratory data analysis, and
preprocessing. No prediction model is trained in this phase.

## Dataset

- **Source:** [Roman Urdu Data Set on Hugging Face](https://huggingface.co/datasets/community-datasets/roman_urdu)
- **Loading code:** `load_dataset("community-datasets/roman_urdu")`
- **Original size:** 20,229 rows
- **Original split:** one `train` split
- **Input feature:** `sentence` (Roman Urdu text)
- **Target:** `sentiment`
- **Classes:** Positive, Negative, and Neutral
- **Cleaned size:** 19,490 rows

The raw dataset is generated by the first notebook, so it does not need to be
downloaded manually.

## Data cleaning summary

The cleaning notebook:

1. converted numeric class IDs to their official readable labels;
2. normalized Unicode, removed invisible characters, and standardized whitespace;
3. removed 113 rows with empty text;
4. removed 106 rows whose normalized text appeared with conflicting labels;
5. removed 520 repeated text/label rows;
6. inspected text-length outliers but kept them because long text can still be valid;
7. saved both the raw and cleaned CSV files.

The cleaned data has no missing values, empty messages, duplicate normalized text,
or known target conflicts.

## Key findings from EDA

- Neutral is the largest class: 8,446 rows (43.34%).
- Positive has 5,810 rows (29.81%).
- Negative is the smallest class: 5,234 rows (26.85%).
- The largest-to-smallest class ratio is 1.61:1, so Phase 2 should report macro-F1,
  precision, and recall in addition to accuracy.
- The median message contains 10 words.
- 23.7% of messages contain five words or fewer, while 18.5% contain more than
  twenty words.
- Character count and word count have a very strong correlation (0.99), so they
  contain mostly overlapping length information.
- The spelling variation visible in common words supports testing both word and
  character n-grams in the classical ML phase.

## Preprocessing decisions

The final model text is lowercased, web links are replaced with `<url>`, usernames
are replaced with `<user>`, and whitespace is standardized. Punctuation, common
words, and Roman Urdu spellings are preserved to avoid removing useful sentiment
information.

The cleaned dataset is split into 15,592 training rows and 3,898 test rows using an
80/20 stratified split with `random_state=42`. There is no repeated normalized text
shared between the two files.

Numeric scaling is not applied directly to sentences. In Phase 2, TF-IDF will
create normalized sparse features for classical models, while neural models will
use tokens and embeddings. Any future numeric feature scaler must be fitted only
on the training set to prevent data leakage.

## How to run

Python 3.11 is recommended.

### 1. Create and activate a virtual environment

On Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

On macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 2. Install libraries

```bash
pip install -r requirements.txt
```

### 3. Open the notebooks

```bash
jupyter notebook
```

Run the notebooks in numerical order. They are already saved with outputs, but
running them again will reproduce the processed files and charts.
